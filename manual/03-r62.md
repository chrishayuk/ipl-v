# §3. R62, and the wrong Q

*Part One, section 3.0, "Simple List Processing", page 26 (PDF page 61).*

R62 locates the first occurrence of the symbol (0) on the list (1): the
output is the name of the cell that holds it, with H5 +, or H5 - if it is
not there. The manual prints it with a deliberate error, and asks: "One of
the Q codes below is wrong; can you spot it?"

Here it is as printed, error and all.

```iplv
R62 AS PRINTED ON PAGE 26               9
                                        2 L                10
                                        2 P                10
                                        2 R               100
                                        2 S                10
                                        5       00
PRESERVE W0, W1; (0) TO W0, (1) TO W1.    R62     J51
START (OR RESUME) SEARCH.                 9-1   10W1
LOCATE THE CELL HOLDING NEXT SYMBOL.              J60
POP W0 AND W1 WHEN NO MORE. QUIT H5-.           70J31
SAVE LOCATION TO RESUME SEARCH.                 20W1
INPUT THE NEW SYMBOL.                           12W1
INPUT SYMBOL BEING SOUGHT.                      11W0
TEST IF SYMBOLS MATCH.                            J2
RESUME SEARCH AT 9-1 IF NO MATCH.               709-1
LOCATION OF MATCHING SYMBOL TO H0.              11W1    J31
                                        5       00
                                          P0    10L1
                                                10S3

                                                  J152  0
                                        5       01
                                          L1      0
                                                  S1
                                                  S2
                                                  S3    0

```

```output
         W1
```

It finishes, with the wrong answer: not the cell holding S3, but the
symbol `W1`. The manual's answer is on the same page: "The erroneous Q-code
is at 9-1. The instruction should be 11W1, since we do not want to search
the list W1 but the list whose name is in the top cell of W1."

Why `W1`, though, is worth following, because it is the kind of thing IPL
does to you. `10 W1` puts the symbol W1 itself in H0, so `J60` looks for
the cell after the cell W1. W1 is a storage cell, and the cell after it
is the top of its own push-down list, made by the `J51` a moment before.
W1 was empty when J51 preserved it, so that cell holds a word of all
zeros, which is exactly what a private termination cell is (Part Two,
section 9.4). J60 takes it for the end of a list, returns it to available
space (section 9.5), and reports no next cell. R62 quits with H5 - and,
as a LOCATE does, the last cell it reached: W1.

If W1 had held something, the copy would not look like a termination
cell, and R62 would go round for ever: J60 finds the copy, `20 W1` puts
its name in W1, the symbol in it is not S3, and `10 W1` starts again from
the cell W1, whose LINK has not changed. Here W1 holds S9 first:

```output
216      S3
         S4
         S7
217      S4
```

`J151` printing from a cell in the middle of a list prints the rest of the
list, which shows which cell came back. When the symbol is not found, the
output is the last cell of the list: that is the convention for every
LOCATE in IPL-V (Part Two, section 9.2), and R62 keeps it without trying,
because J60 leaves its input in H0 when there is no next cell.
